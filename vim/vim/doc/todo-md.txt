*todo-md.txt*  Highlighting and mappings for todo.md outlines

Named todo-md rather than todo so it does not shadow vim's own |todo.txt|,
which is the list of known bugs in vim itself.

Any file named todo.md, or ending in .todo.md, gets filetype "todo". Nothing
else changes: every other markdown file still belongs to vim-pandoc.

==============================================================================
1. THE FORMAT                                                 *todo-md-format*

A plain indented outline. Two spaces per level, one bullet per line: >

    * Measurement                     a section: a bullet with no checkbox
      * lectures @due(2026-09-06)     ...which nest
        * [ ] Finish lit review       an open task
        * [x] Book the room           a done task
        * [ ] Get grant #p1 @waiting for Katie
<
The only structural distinction is the checkbox. A bullet with one is a task;
a bullet without one is a heading for the bullets under it.

Tags are @name, @name(argument), or #name, and can go on any line. Three have
a meaning:

    @due(YYYY-MM-DD)   when the task is due. The date format is fixed: it is
                       what makes dates sortable and comparable as plain text.
    @waiting           the task is blocked. Whatever follows, up to the next
                       @ or #, is read as a note about what is being waited
                       on, and is dimmed with the tag.
    @done(YYYY-MM-DD)  when the task was finished. Written by <leader>d, and
                       removed again if the task is reopened. It needs no
                       colour of its own: it only ever appears on a finished
                       line, which is dimmed whole.
    @now               the task is one of the few being worked on now. It
                       highlights as an ordinary tag; what it is really for is
                       putting the task in |:TodoSummary|.
    #p1                high priority. Other #tags, #p2 included, are ordinary
                       tags with no meaning attached.

Every other @tag and #tag is highlighted too, just without a special colour.
Inventing one costs nothing and breaks nothing.

==============================================================================
2. HIGHLIGHTING                                         *todo-md-highlighting*

    todoSection     a top-level heading, at column 0
    todoProject     an indented heading
    todoBox         the [ ] or [x] marker
    todoDone        a whole finished line, tags and all
    todoDue         a @due tag
    todoOverdue     a @due tag whose date is before today
    todoDueSoon     a @due tag due within |g:todo_soon_days|, today included
    todoWaiting     a @waiting tag and its note
    todoPriority    a #tag
    todoTag         any other @tag

The three states of a due date are meant to read as a ramp: orange for a date
still out of reach, yellow once it is close enough to plan around, red for one
already past.

Only the date changes colour. Whole rows were highlighted here at one point -
bold for @now, and for a deadline close or missed - and it read as clutter:
bold lines pile up, and molokai draws headings bold already, so weight stopped
distinguishing anything. Urgency is said once, by the colour of the date, and
answered properly by |:TodoSummary|.

Each group is linked to a standard group with |:highlight-default|, so any
colorscheme gives them something sensible and any of them can be overridden
in the vimrc without touching the syntax file: >

    highlight link todoPriority ErrorMsg
<
todoOverdue and todoDueSoon are not written in the syntax file, because
"before today" is not a fixed pattern. todo#Refresh() finds those dates and
paints them with |matchaddpos()|, which sits above syntax highlighting and so
wins without any priority juggling. The cost is that matches belong to the
window rather than the buffer, which is why ftplugin/todo.vim re-runs the
function whenever the buffer is displayed or edited, and clears the matches
when the window moves on to another file.

3. MAPPINGS                                                 *todo-md-mappings*

All buffer-local, all normal mode, with the leader as set in the vimrc (,).

    <leader>n       Open a new task below the cursor and start typing it.
                    Next to another task the new one is a sibling; under a
                    heading it goes one level in, which is where it belongs
                    just after typing the heading.

    <leader>d       Flip [ ] and [x] on the current line, and stamp
                    @done with today's date. Reopening a task removes the
                    stamp; ticking one that already carries a stamp rewrites
                    it rather than adding a second. Does nothing at all on a
                    line without a checkbox.

    <leader>u       Set or replace @due on the current line. Prompts, with
                    today's date filled in, or with the date already on the
                    line so that moving it by a few days is a small edit.
                    Anything that is not YYYY-MM-DD is refused.

    <leader>g       Go to the summary panel, opening it if it is not up.
                    The panel never takes the cursor by itself, so this is
                    the way in. From there <C-w>p returns, and q closes it.

    <leader>G       Show or hide the summary panel - see |:TodoSummary|.

Folding is by indent, with everything open ('foldlevel' 99), so |zc| closes a
section and |zR| opens them all again.

                                                                *:TodoSummary*
:TodoSummary    Show every task worth doing now in a small window under the
                file, and leave the cursor where it was. Opens by itself
                whenever a todo file is displayed, and closes with it.

                There are five ways to qualify, and a task is listed under
                the first that applies to it:

                    now     tagged @now
                    late    the @due date is before today
                    today   the @due date is today
                    p1      tagged #p1
                    soon    the @due date is inside the next few days

                @now wins outright, over a missed deadline included. It is
                the only rule here that is a decision; the rest are
                inferences from a date, and a decision beats an inference.

                Entries are sorted in that order, then by date, so the list
                reads from the most overdue thing down to the merely
                approaching. Each carries the headings it sits under, since
                "Get grant" on its own could be anything: >

    late  Measurement > research | Measurement review paper @due(2026-08-05)
    now   WET | Upgrade Slides @now
    p1    Shipuzim | Figure out door lock #p1
<
                A @waiting task is left out. It is blocked on somebody else,
                so listing it among things to do only teaches you to skip
                lines. Two things override that: once it is late, chasing it
                is precisely the thing to do, and if you have tagged it @now
                then you have already decided.

                The panel is there to be glanced at while you work in the
                file, which is why it never takes the cursor. An fzf picker
                over the same list was tried and removed: fzf is modal, so
                while it is up it owns the keyboard, and it can only answer
                "which one of these" before disappearing again. That turned
                out to be a question worth asking far less often than "what
                is on today".

                In the panel:

                    <CR>    jump to that task in the file
                    q       close the panel

                The panel never changes what closing the file does. It takes
                itself down before a |:quit| so that vim sees the window
                layout it would have seen had the panel never existed, and if
                it is ever left as the only window - after |:bdelete|, say -
                it hands the window to another buffer rather than deciding on
                its own that vim is finished. Only with nothing else open at
                all does it quit.

                Note that :q on the last window quits vim whether or not
                other buffers are loaded. That is vim, not this: |:bdelete|
                is the one that puts a file away and leaves you where you
                were.

                It rebuilds itself as the file changes, so ticking a task off
                takes it out of the list. That happens on a zero-delay timer
                rather than immediately: building the panel means creating a
                window and stepping back out of one, and doing that from
                inside the event that triggered it puts the cursor in the
                wrong place at startup. The timer also coalesces a burst of
                edits into one rebuild.

                                                             *g:todo_summary*
                Set to 0 to stop the panel opening by itself. |:TodoSummary|
                still works. >

                    let g:todo_summary = 0
<
                                                      *g:todo_summary_height*
                The most lines the panel will take. Default 8; a shorter list
                gets a shorter window. >

                    let g:todo_summary_height = 12
<

                                                          *g:todo_soon_days*
                How far ahead "soon" reaches, in days. Default 3.

                It governs both the colouring and this list, deliberately: a
                date the file draws as approaching is a date the picker
                gathers, and there is only one idea of soon to hold in your
                head. >

                    let g:todo_soon_days = 7
<

4. HOW IT IS WIRED                                             *todo-md-files*

    after/ftdetect/todo.vim   filename to filetype
    syntax/todo.vim           the static highlighting
    ftplugin/todo.vim         buffer options, mappings, refresh autocmds
    autoload/todo.vim         the functions behind all of it

This is the layout of a standalone plugin. If it ever outgrows the dotfiles
repository, the four files plus this one move to their own repository, a Plug
line goes in the vimrc, and nothing else changes.

The one subtle part is the first file. vim-pandoc claims every *.md for
filetype=pandoc, and where two autocmds both fire, the one registered last
wins. ftdetect files are read in 'runtimepath' order and ~/.vim/after is last,
which is the only reason that file sits under after/. It also has to clear
b:did_ftplugin, which vim-pandoc sets to suppress markdown's ftplugin and
which would otherwise suppress this one too. The comments in the file say the
same thing at more length.

This help file is indexed by `make vim`. After adding a tag to it by hand,
run: >

    :helptags ~/.vim/doc
<

5. IDEAS, NOT IMPLEMENTED                                      *todo-md-ideas*

None of this is decided. It is written down so the reasoning does not have to
be reconstructed later, and so that the shape of the thing stays deliberate.

A longer horizon~
    |:TodoSummary| answers "what today"; nothing answers "what this month".
    The same loop with the near-date rules dropped would list every dated
    task in order. Unclear whether that is a second command, an argument to
    the existing one, or a thing best done by reading the file.

Archiving~
    A function moving [x] lines to a "* Done" section, or to a separate
    todo-archive.md. The @done stamps are already being written, so an
    archive would be worth reading rather than being a heap of undated
    lines. Open question: whether an archive is wanted at all, or whether
    finished tasks should simply be deleted once they have been seen.

Date completion~
    @due( then <c-x><c-o> offering today, tomorrow, next monday. The template
    already exists in autoload/cite.vim, and fzf is already installed. The
    question is whether typing eight digits is annoying enough to justify it.

Overdue count~
    In the statusline or the sign column, reusing the scan todo#Refresh()
    already does. Only useful if todo.md is open most of the day.

Opening the file~
    nnoremap <leader>t :e ~/todo.md<CR> in the vimrc: the one piece of this
    that cannot be filetype-local, because it has to work from anywhere.

Sorting~
    Sort the tasks under the heading by due date, undated last. Small, and
    conflicts with keeping the list in a deliberate manual order.

Recurrence~
    @every(week) respawning a task when ticked. This is where a todo file
    stops being a text file and starts being an application; probably the
    line worth not crossing.

Ageing @waiting~
    @waiting(2026-08-01) growing more insistent in colour the longer it sits.
    The mechanism is already there - todo#Refresh() compares dates and paints
    - so this is one more branch in that loop.
